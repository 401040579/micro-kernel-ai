# MicroKernel AI - 用户体验设计文档

## 1. 设计原则

### 核心原则：零学习成本

MicroKernel AI 的终极目标是让用户觉得"不需要学就会用"。设计的每个决策都围绕这个原则展开。

| 原则 | 含义 | 反面例子 |
|------|------|---------|
| **对话优先** | 所有操作都能通过对话完成，UI按钮是快捷方式而非必须 | 必须在菜单里找功能 |
| **渐进式复杂度** | 初始界面极简，功能随用户需求逐步展现 | 一上来就展示所有功能 |
| **即时反馈** | 每个操作都有可见的响应，尤其是AI处理过程 | 用户等待时没有进度提示 |
| **容错友好** | 说错了可以轻松纠正，做错了可以随时撤销 | 无法撤销的操作 |
| **自然语言** | 界面文案像人说话，不用技术术语 | "配置API端点"、"设置状态管理器" |

### 视觉风格

- **风格基调**：现代、简洁、温暖、科技感但不冰冷
- **主色调**：靛蓝色 (#6366f1) — 科技感但不刺眼
- **辅助色**：翠绿色 (#10b981) 表示成功/生成、琥珀色 (#f59e0b) 表示提示、玫红色 (#f43f5e) 表示警告
- **背景**：深色模式为默认（#0f172a），支持浅色模式切换
- **字体**：中文用"思源黑体"，英文用"Inter"，等宽用"JetBrains Mono"
- **圆角**：统一使用12px圆角，营造柔和感
- **动效**：流畅但克制，避免花哨动画分散注意力

   - 支持截图/录屏分享

3. **进度反馈**
   - 生成过程展示细粒度进度（解析需求 → 匹配插件 → 生成代码 → 编译 → 渲染）
   - 每个阶段有预估时间
   - 生成过程中可以继续对话补充需求

## 3. 交互流程详细设计

### 3.1 语音交互流程

```
状态机：
┌─────────┐   点击麦克风    ┌──────────┐
│  待命态  │ ──────────────→ │  监听态   │
│ (默认)  │                 │ (录音中)  │
└─────────┘                 └────┬─────┘
     ▲                          │
     │                     语音结束检测
     │                     (1.5秒静默)
     │                          │
     │                          ▼
     │                    ┌──────────┐
     │                    │  识别态   │
     │                    │ (转文字)  │
     │                    └────┬─────┘
     │                          │
     │          ┌───────────────┤
     │          ▼               ▼
     │    ┌──────────┐   ┌──────────┐
     │    │ 确认态    │   │  错误态   │
     │    │ (展示文字)│   │ (重试?)  │
     │    └────┬─────┘   └────┬─────┘
     │         │              │
     └─────────┴──────────────┘
```

**语音交互设计要点**：
1. **麦克风按钮位置**：始终在输入框左侧，一键可达
2. **录音反馈**：麦克风图标变红+脉冲动画，显示音量波形
3. **文字实时展示**：语音识别结果实时显示在输入框中
4. **确认机制**：识别完成后自动填入输入框，用户可修改后再发送（不自动发送，防止误操作）
5. **错误处理**：识别失败时提示"没听清，请再说一次"或"点击编辑手动修改"
6. **快捷口令**：支持语音命令如"撤销"、"重做"、"部署"、"换个样式"

### 3.3 错误处理设计

| 错误场景 | 用户看到的信息 | 可选操作 |
|---------|--------------|---------|
| AI无法理解需求 | "我没太理解你的意思，能换个方式描述一下吗？比如：你想做什么类型的应用？" | 重新输入 / 选择模板 |
| 生成过程失败 | "生成遇到了一点问题，正在自动重试..." | 自动重试 / 手动重试 / 简化需求 |
| 语音识别失败 | "没听清楚，请再说一次，或者手动输入" | 重新录音 / 切换文字输入 |
| 网络断开 | "网络似乎断了，已保存你的进度，恢复后可继续" | 自动重连 / 离线模式 |
| 生成内容不满意 | （不算错误，但要引导）"试试告诉我哪里不满意，比如'列表太丑了'或'加个搜索框'" | 继续对话修改 |
| 超出免费额度 | "今天的免费次数用完了，升级Pro可无限使用" | 升级 / 明天再来 |

## 5. 首次使用引导 (Onboarding)

### 5.1 零门槛引导流程

```
1. 用户从落地页直接输入需求（无需注册）
   ↓
2. 展示生成过程和结果（Aha Moment！）
   ↓
3. 弹出轻量提示："注册保存你的项目"
   · Google/微信/手机号一键注册
   · 跳过（但提示项目将在24小时后删除）
   ↓
4. 注册成功后，3步引导提示（tooltip形式，不阻断使用）：
   · "这里可以语音输入"（指向麦克风）
   · "这里可以预览效果"（指向预览区）
   · "说'撤销'可以回退修改"（指向对话框）
   ↓
5. 引导结束，自由探索
```

### 5.2 设计要点
- 绝不使用多步注册流程
- 绝不在使用前强制看教程
- 引导提示最多3个，可以一键跳过
- 首次使用的Demo场景应在3轮对话内展示完整价值
